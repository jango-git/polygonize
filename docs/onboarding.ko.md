# Tesselot - 아키텍처

## 들어가며

Tesselot는 브라우저에서 동작하는 로우폴리(low-poly) 이미지 에디터입니다. 사용자는 이미지 위에 안내 도형(**모디파이어**: 직선, 곡선, 원)을 그리고, 애플리케이션은 나머지 공간에 점을 뿌려 삼각분할한 뒤 색을 입힙니다. 사용자에게 무엇을 제공하는지는 README를 참고하세요. 이 문서는 코드 구조를 다룹니다.

코드를 읽기 전에 반드시 이해해야 할 핵심은, 파이프라인이 완전히 비파괴적(non-destructive)이라는 점입니다. 상태는 **source**(사용자가 지정한 것 - 이미지, 설정, 도형 트리)와 **derived**(점, 삼각분할, 색상)로 엄격히 분리되어 있습니다. 저장되고 히스토리에 남는 것은 source뿐이며, derived는 변경이 일어날 때마다, 그리고 로드할 때마다 source로부터 다시 계산되고 절대 저장되지 않습니다.

이 분리에서 나머지 아키텍처가 거의 모두 따라 나옵니다. undo가 저렴한 이유(스냅샷은 source뿐), 모든 것이 결정론적인 이유(하나의 source는 항상 하나의 derived를 만듦), 무거운 계산이 백그라운드로 빠지는 이유(derived 계산은 비쌈), 그리고 데이터가 한 방향으로만 흐르는 이유(source에서 derived로, 절대 반대 방향은 없음)까지 전부입니다.

익숙한 개념으로 비유하면 Redux/Flux의 단방향 데이터 흐름과 비슷합니다. 하나의 상태, 명령을 통해서만 변경, 구독자가 이벤트에 반응하는 구조에 더해, computed/reselect처럼 그 위에 얹힌 계산된 상태 레이어가 있는 셈입니다.

## 다섯 개의 레이어

| 레이어 | 폴더 | 담당 | 알고 있는 대상 |
|---|---|---|---|
| **UI** | `src/ui/` | 입력: 그리기, 패널, 도구, 단축키 | 모델(명령을 보냄) |
| **모델** | `src/document/` | source + derived, 히스토리, 이벤트 | 자기 자신 위의 레이어는 모름 |
| **도메인** | `src/domain/` | 순수 로직: 도형이 점으로 변환되는 방식, WASM과의 연결 | 모델이 이를 호출함 |
| **렌더** | `src/preview/` | three.js로 이미지와 삼각형을 그림 | 모델을 읽기만 함 |
| **네이티브** | `crates/` | Rust->WASM: 무거운 기하 연산과 색상 계산 | 아무것도 모름, 순수 함수 |

그 외에 보조 폴더가 몇 개 더 있습니다: `persistence/`(저장 및 내보내기), `settings/`, `i18n/`.

흐름의 원칙: UI는 모델만 변경하고, 렌더는 모델만 읽으며, 이 둘은 서로 직접 통신하지 않습니다. 이들을 연결하는 것은 모델 내부의 이벤트 버스이며, 이것이 바로 단방향 사이클입니다.

## 데이터 흐름

핵심 시나리오는 "마우스 스트로크 한 번에서 다시 칠해진 삼각형까지"입니다.

```
   사용자              (1) UI가 입력을 감지
       |
       v
   (2) 명령이 SOURCE를 변경: 도형을 추가하거나 이동
       |
       v
   (3) 재계산: source -> 점 -> 삼각형      [무거운 작업, 백그라운드 워커에서]
       |
       v
   (4) 모델이 결과를 플랫 버퍼에 담고 "완료" 이벤트를 발행
       |
       v
   (5) 렌더가 이벤트를 듣고 화면의 이미지를 갱신
       |
       +--> (6) 동시에 삼각형 색상이 계산됨 -> 또 다른 이벤트 -> 다시 칠하기
```

이 사이클을 반응성 있게 만드는 세 가지 장치가 있습니다.

- **프레임당 한 번의 재계산.** 드래그 중에는 마우스 이벤트가 초당 수십 번씩 쏟아지지만, 재계산은 프레임당 한 번을 넘지 않도록 제한되며 중간 위치들은 버려집니다.
- **렌더는 절대 기다리지 않는다.** 백그라운드에서 정확한 색상을 계산하는 동안, 삼각형은 즉시 근사 색상으로 표시되고, 완성된 색상은 별도의 이벤트로 도착해 그 위에 덮어씌워집니다.
- **불필요한 할당이 없다.** 삼각형은 객체가 아니라 긴 플랫 숫자 배열로 존재하며, 렌더와 내보내기 모두 이 배열을 직접 읽습니다.

## 작업 지도

| 바꾸고 싶은 것... | 살펴볼 곳... |
|---|---|
| 그리기 도구의 동작 | `src/ui/tools/` |
| 오른쪽 패널(도형 트리, 그룹) | `src/ui/panel/` |
| 도형이 점으로 변환되는 방식 | `src/domain/modifiers/` |
| 점 배치 알고리즘 / 삼각분할 | `crates/pipeline/` |
| 삼각형 색상 계산 방식 | `crates/color/` |
| 그리기, 카메라, 오버레이 | `src/preview/` |
| 저장 형식 / undo | `src/document/` |
| 디스크 저장 / SVG, PDF, PNG 내보내기 | `src/persistence/` |

## 레이어별 상세

### 모델 (`src/document/`)

상태는 `DocumentData`(`types.ts`)라는 단일 객체이며, 정확히 이 경계를 따라 나뉩니다.

- **Source** (저장됨, 히스토리에 존재): `image`, `seed`, `seedSettings`, `colorSettings`, `stack`(도형 트리).
- **Derived** (재계산됨, 저장되지 않음): `points`와 렌더용 플랫 버퍼 - `renderPositions`(정점당 xyz), `renderColors`(삼각형당 rgb), `triangleCount`.

변경이 모델을 통과하는 과정:

- `store.ts` - 단일 가변 상태 객체 (`store.data()`).
- `commands/` - 상태를 변경하는 유일한 방법, reducer에 해당. 명령이 source를 제자리에서 수정하고 커밋을 호출하면, `commit.ts`가 재계산이 필요한지(`commitStructural`, 기하 편집용) 아니면 히스토리 스텝만 기록하면 되는지(`commitViewOnly`, 예를 들어 폴더 접기)를 판단합니다.
- `commands/pipeline.ts` - 재계산(`evaluatePoints`). "동시에 하나의 요청만 진행"이라는 원칙으로 동작합니다. 아무리 많은 수정이 들어와도 워커에는 한 번에 하나의 계산만 진행되지만, 마지막 계산은 반드시 끝까지 완료됩니다.
- `commands/recompute.ts` - 결과를 플랫 버퍼로 정리(`buildGeometry`)하고 계산된 색상을 적용(`applyColorGrid`).
- `signals.ts` - 이벤트 버스(`ferrsign` 기반). 모델은 아무것도 직접 그리지 않으며, "점이 바뀌었다", "삼각형이 바뀌었다", "source가 통째로 교체되었다" 같은 사실만 알릴 뿐, 렌더/패널/히스토리 같은 구독자가 반응합니다.
- `history.ts` - undo/redo. 스냅샷은 source뿐이므로 이미지조차 포함하지 않아 저렴하며, 드래그 제스처 전체가 하나의 스텝으로 합쳐집니다.
- `selectors/` - 모델을 외부로 읽어내는 지점. 명령을 거치지 않은 채 상태가 훼손되지 않도록 복제본을 반환하지만, 예외적으로 플랫 버퍼는 속도를 위해 참조 그대로 반환합니다.

도형 트리(`stack`)는 Blender의 컬렉션처럼 단일 계층 구조입니다. 각 요소는 독립된 도형이거나, 자식을 가진 그룹입니다. 그룹은 "접기"(보기 전용)와 "비활성화"(계산에서 제외)를 지원합니다. 스택 내 순서는 의미를 가집니다. 트리에 대한 구조적 연산은 `commands/stackTree.ts`, `modifierCommands.ts`, `groupCommands.ts`에 있습니다.

### 도메인 (`src/domain/`)

DOM이나 three.js에 의존하지 않는 로직입니다. 유일한 예외는 `<canvas>`에서 픽셀을 읽는 `imageSource.ts`입니다. 크게 두 가지 주제로 나뉩니다.

- `modifiers/` - 각 도형이 점과 제약 간선(`ModifierResult`)으로 변환되는 방식: `path.ts`(꺾은선 또는 Catmull-Rom 스플라인), `bezier.ts`(대칭 핸들을 가진 베지어 곡선), `circle.ts`. 공통 조립기는 `result.ts`.
- 네이티브 레이어로의 연결: 각 WASM crate마다 "파사드 + 워커 + 클라이언트" 삼총사가 있습니다. 무거운 계산은 Web Worker에서 이루어지며, 데이터는 복사 없이 transferable 배열로 경계를 넘습니다.

기타: `rng.ts`(결정론적 의사난수 생성기), `colorGrid.ts`(공간 색상 검색), `groupColor.ts`(그룹의 색상은 그룹 이름에서 유도됩니다 - 이름을 바꾸면 색도 바뀝니다).

### 렌더 (`src/preview/`)

모델의 이벤트를 엄격히 한 방향으로만 듣고, 모델로 되돌아가는 참조는 없습니다. 월드 좌표는 이미지 좌표와 일치하며(Y축이 아래 방향), 카메라는 직교(orthographic) 카메라입니다.

- `preview.ts` - 코디네이터: 하나의 씬, 하나의 렌더러, 여러 레이어.
- 각 레이어는 자신의 three.js 객체를 소유합니다: `triangleLayer.ts`(삼각형; 매 프레임 재생성하지 않고 버퍼를 재사용), `imageLayer.ts`(원본 이미지), `pointLayer.ts`(시드 점), `overlayLayer.ts`(선택, 핸들, 드래프트 등 편집용 오버레이).
- `receiving.ts` - "모델 이벤트 -> 레이어 호출" 브리지. 여기서 최적화도 이루어집니다. "다시 칠해짐" 이벤트에는 색상만 갱신하고, "재구성됨" 이벤트에는 위치와 색상을 모두 갱신합니다.
- `viewport.ts` - 카메라와 화면<->이미지 좌표 변환(줌, 팬).

### UI (`src/ui/`)

프레임워크 없는 명령형 DOM/캔버스 코드입니다. 패널은 이벤트를 받을 때마다 자신의 DOM을 다시 구성합니다. UI 상태는 절대 직접 변경하지 않으며, 오직 명령을 통해서만 변경합니다.

- `tools.ts` (`ToolController`) - "선택 / 그리기 / 드래그" 모드 사이를 오가는 상태 머신으로, 캔버스 위의 입력을 감지합니다.
- `tools/` - 도구 구현: 그려지는 도형의 드래프트(`*Draft.ts`)와 점을 드래그하는 `dragSession.ts`. "프레임당 한 번의 재계산"과 제스처를 undo 한 스텝으로 합치는 로직이 여기 있습니다.
- `panel/` - 오른쪽 패널: 그룹과 드래그 앤 드롭이 있는 도형 트리(`stackView.ts`, `dnd.ts`).
- 나머지 - 도구 팔레트, 선택과 하이라이트, 단축키, 토스트 알림.

### 네이티브 레이어 (`crates/`)

독립된 두 개의 crate로, 각각 로드한 이미지를 자체적으로 캐싱해 호출마다 이미지를 다시 전송하지 않도록 합니다.

- `crates/pipeline/` - 기하 연산: `sobel.rs`(이미지 경계에 따른 밀도 맵 - 변화가 급격한 곳일수록 점이 촘촘해짐), `seeding.rs`(가변 반경을 사용하는 Bridson 방식의 점 배치), `triangulate.rs`(제약 조건이 있는 들로네 삼각분할, `spade` crate 사용), `contours.rs`(이미지 윤곽선을 편집 가능한 도형으로 추적, Canny 알고리즘 사용).
- `crates/color/` - 색상: 각 삼각형 아래의 색을 샘플링하고(평균 또는 중앙값), 빠른 검색을 위한 공간 그리드를 구축합니다. 색상 전용 워커에서 동작합니다.

결정론적 동작에 결정적인 부분들 - 난수 생성, 점 배치, 샘플링 - 은 이전 TS 구현과 비트 단위로 정확히 일치하도록 의도적으로 맞춰져 있습니다. 하나의 seed는 어떤 실행 환경에서도 항상 같은 결과 이미지를 만들어냅니다.

## 빌드

- `npm run build:wasm` - 각 crate마다: cargo -> wasm-bindgen(`--target web`) -> wasm-opt(`-Oz`). 글루 코드는 `src/generated/`(gitignore 대상)에 놓이고, `.wasm`은 `dist/`로 복사되어 런타임에 로드됩니다.
- `npm run build` = `build:wasm` 다음 `rollup -c`. `npm run dev`는 watch(`-w`)를 추가로 실행합니다.
- 배포는 정적(GitHub Pages)이며, 백엔드가 없습니다.

## 요약

애플리케이션은 오직 source만 저장합니다. 사용자는 UI를 통해 이를 수정하고, 모델은 이를 백그라운드의 Rust/WASM 파이프라인을 거쳐 플랫 버퍼로 만들며, 렌더는 그 버퍼를 그대로 반영할 뿐입니다. 나머지 모든 것은 이 하나의 분리에서 비롯된 결과입니다.
